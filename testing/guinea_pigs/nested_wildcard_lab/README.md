# `nested_wildcard_lab`: RedAmon guinea pig for scope groups, nested wildcards and org domains

A self-contained DNS + web lab for the Domain-batch scope model: exact hosts and
`*.` wildcards at any depth, scan roots below the registrable (org) domain, the
Root checkbox, ownership TXT at the scan root or the org, and org-level checks
(SPF/DMARC/DNSSEC) that run once per org. It is also the regression lab for the
recon pipeline on multi-host projects.

Everything is on reserved names (`*.nwlab.test`, `*.nwlab-two.test`, RFC 2606)
and on `192.88.99.50-79`. **Scan nothing else from this harness.**

## What it serves

| Service | IP | Role |
|---|---|---|
| `labdns` (CoreDNS) | `192.88.99.53` | authoritative for `nwlab.test` and `nwlab-two.test` only; every other name is REFUSED, so it never recurses |
| `web1` (nginx) | `192.88.99.60` | every `nwlab.test` vhost on 80 + 443 |
| `web2` (nginx) | `192.88.99.61` | every `nwlab-two.test` vhost on 80 + 443 |
| `web3` (nginx) | `192.88.99.62` | `edge` and `mixed` on 80 + 443: the address the `FULL` scenario's Rules of Engagement exclude |
| `web4` (nginx) | `192.88.99.63` | `plain.nwlab.test`, **HTTP only** (nothing on 443); its bare-IP root 302s to `edge` |
| `web5` (nginx) | `192.88.99.64` | X of `two.nwlab.test` (80, 443); its bare-IP :80 root 302s to `www.nwlab-two.test` |
| `web6` (nginx) | `192.88.99.65` | Y of `two.nwlab.test` (443, 8443, an FTP-style banner on 21); its bare-IP :443 root 302s to `169.254.169.254` |
| `pcap2`..`pcap5` (tcpdump) | web2..web5's network namespace | every IPv4 packet web2..web5 receive, in `out/pcap/` |

Every vhost returns `<h1>{host}</h1>` from a fixed map (never from the Host
header), so httpx results are per host and no host-header reflection appears.
web1 also serves `vhost-only.nwlab.test`, which no zone has: the one name the
vhost/SNI scenario `VH` must report as a hidden vhost, while every name DNS
points at web1 must not be (plan 07).

### `nwlab-two.test`: the "dirty" org (A records → web2)

| Name | Records | Validates |
|---|---|---|
| `nwlab-two.test` | A, NS `ns1`; **no SPF, no DMARC** | SPF-missing and DMARC-missing, once, on `Domain(nwlab-two.test)` |

### Certificates (generated by `setup.sh` into `certs/`, gitignored)

- **web1** SANs: `api`, `v1.api`, `v2.api`, `admin.v1.api`, `internal.v1.api`, `www`, `shop`, `mail`, `secret` (all `.nwlab.test`). A `*.api` ENUMERATE group may inject only the four `*.api` names; an EXACT group injects nothing.
- **web2** SANs: `nwlab-two.test`, `www`, `portal`, `api`, `v1.api`, `v2.api` (all `.nwlab-two.test`).
- **wild** SANs: `wild`, `real.wild`, `admin.wild`, `dev.wild`, `vpn.wild`, `staging.wild` (all `.nwlab.test`). web1 serves it for `wild.nwlab.test` and every name under it, web2 for `real.wild.nwlab.test`. An existing lab gets it from the next `./setup.sh`, which only generates missing certificates; nginx will not start without it.

### Web content

- `https://api.nwlab.test/` loads `/static/app.js`, which references `https://js-only.v2.api.nwlab.test/x` (inside `*.api`) and `https://cdn.nwlab.test/lib.js` (a sibling outside it).
- `https://api.nwlab.test/openapi.json` and `https://www.nwlab.test/openapi.json` are two small OpenAPI 3 documents with distinct paths, for two partial OpenAPI runs on scan roots of the same org at the same time.

### E2E-B hosts: Rules of Engagement and per-address ports

The `FULL` scenario runs the whole pipeline on `*.nwlab.test` with the Rules of
Engagement excluding `192.88.99.62/32` and the name `shop.nwlab.test`. Each
name below is a must-stay-silent case next to one that must fire.

| Name | Records | Must hold |
|---|---|---|
| `edge` | A → web3 only | never probed by any tool: no packet reaches web3, no asset or finding names it |
| `mixed` | A → web2 **and** web3 | a name with any excluded address is never sent by name (no Host or SNI `mixed` on web2 either); web2 is still checked as a bare address |
| `ghost` | CNAME → `gone.nwlab-two.test` (NXDOMAIN) | a name with no address under an IP/CIDR exclusion is refused and kept "not checked" |
| `shop` | A → web1 (only in web1's certificate SANs) | excluded by name: discovered through the SANs, never requested (R-1) |
| `plain` | A → web4 (80 only) | checked on :80 (Basic auth over HTTP fires), never connected on 443, never "unreachable" |
| `two` | A → web5 (X) and web6 (Y) | 80 under X only, 8443 and 21 under Y only, 443 under both; the banner on 21 is read on Y and never tried on X |
| web4/web5/web6 bare IPs | 302 to `edge`, to `www.nwlab-two.test` (outside the project) and to `169.254.169.254` | a direct-IP check records the redirect and sends none of the three hops |
| `api` page | links `https://v1.api.nwlab.test/` and `https://shop.nwlab.test/` | an EXACT group's crawl requests neither (S-9); `shop` is also the RoE case above |

`check_lab_traffic.py --since <RUN_START> --expect excluded` asserts the
traffic half from web1..web6's access logs (one line per request with its
Host and SNI) and the captures: a SYN or a TLS handshake leaves no log line,
only a packet. A kernel `connect()` SYN carries TCP timestamps and a port
scanner's raw SYN does not, which tells a check's probe of a closed port from
the port scan's own. `--expect control` is the must-fire half: a run without
the exclusion reaches web3 and `mixed`, which proves the capture sees it.

`lab_toggle.sh` switches a host for the next run through a runtime include
under `out/extra/` (the tracked configuration never changes):
`plain-fixed` / `plain-auth` (the Basic auth finding goes away / comes back),
`x8443 on|off` (X of `two` listens on 8443 too, for a partial Nmap), and
`dmarc drop|fixed|off`, which recreates `labdns` from a tracked Corefile variant:
`_dmarc.nwlab-two.test` goes unanswered / `nwlab-two.test` publishes a DMARC
record / the default zones (scenario `SECDNS`, R-24).

Under an IP or CIDR exclusion naabu is handed addresses only, so naabu works
in `FULL` although it cannot resolve a lab name (Lab limitations). masscan
stays off there too.

### Scenario `WC`: wildcard DNS under a scan root (plan 08)

RedAmon's own wildcard control probes each zone with random labels; when they
resolve, a name whose addresses are all the wildcard's is dropped, and the zone
node carries `is_wildcard_zone` and `wildcard_ips`. In production most such names
come from brute force, but the lab has none (see Lab limitations), so the names
arrive through the `wild` certificate's SANs, the merge every certificate name
goes through: `admin`, `dev`, `vpn` and `staging.wild` are dropped, `real.wild`
is kept, and `Subdomain(wild.nwlab.test)` is stamped `is_wildcard_zone = true`,
`wildcard_ips = [192.88.99.60]`. A certificate name merged after httpx becomes a
scan target (the run's `dns.subdomains`, crawled by resource enumeration), not a
Subdomain node, unless tlsx or vhost/SNI writes it, and neither runs here; so the
checks that tell kept from dropped read the run's recon JSON (`recon_json:` in
`expected_results.yaml`). `WC-DNSOFF` runs the
same hosts with DNS resolution off: no zone is checked and nothing reads as
resolved. Without DNS httpx gets no target here, so no name reaches the control
unchecked; the `wildcard_control` note for that case is unit-tested.
The puredns half of plan 08 cannot run here either: discovery returns no lab
name, so puredns always gets an empty list. It is unit-tested
(`recon/tests/test_puredns.py`).

## Run it

```bash
./setup.sh                     # network (through supply_chain_target), certs, containers
./host_dns_enable.sh            # once per network creation (polkit; over SSH: sudo)
# ... scans ...
./teardown.sh                  # containers only; the shared network stays
./host_dns_disable.sh           # optional
```

### The network

The lab joins `redamon_sc_lab` (`192.88.99.0/24`) as an **external** network.
That network belongs to the `supply_chain_target` compose project, which declares
it; two compose projects cannot each create the same subnet. `setup.sh` creates it
through that project (`up --no-start`) when it is missing: a plain
`docker network create` would lack the compose labels, and the supply-chain
harness would then refuse it. Taking the supply-chain lab `down` while this lab is
attached fails, and recreating the network loses the DNS hookup below.

Why this prefix rather than loopback or a documentation range: recon's Python SSRF
guard (`is_url_safe_to_probe`) refuses loopback, RFC 1918 and every TEST-NET range,
so JS recon would fetch nothing. See [`../supply_chain_target/README.md`](../supply_chain_target/README.md).

### The routing gate: run it before EVERY scan

`192.88.99.0/24` is a **public** prefix (RFC 7526, 6to4 anycast). While the lab
bridge is down, this host routes it to the internet. Before every recon, partial
recon or schedule trigger:

```bash
ip route get 192.88.99.60 | grep -q ' dev br-' && resolvectl query v1.api.nwlab.test
```

Stop if either fails. The gate proves the **kernel** route only: a raw-packet
tool that picks its own adapter ignores it, which is why masscan stays disabled.

### Host DNS hookup

Recon and its scan containers run with `network_mode=host` and resolve through
the host's systemd-resolved stub (`127.0.0.53`); dnspython ignores `/etc/hosts`.
`host_dns_enable.sh` routes **only** `~nwlab.test` and `~nwlab-two.test` to
`192.88.99.53`, on the lab bridge link, with `default-route false`, so no other
name ever reaches the lab DNS. Verify:

```bash
resolvectl query v1.api.nwlab.test             # 192.88.99.60
dig +short @127.0.0.53 TXT _redamon-verify.nwlab.test
dig +short @127.0.0.53 example.com             # still resolves normally
```

### Lab project settings

All are existing project settings, passed to `create_project` as `settings`:

| Setting | Value | Why |
|---|---|---|
| `masscanEnabled` | **false** | **Never enable it here.** masscan injects raw frames through the adapter of the *default* route and ignores the kernel route to the lab bridge, so a masscan of `192.88.99.60` reaches the real 6to4 relay on the internet. The routing gate cannot catch this. The webapp default is `true` (Prisma) while recon's own default is `false`, so a project created without this key runs masscan. |
| `naabuEnabled` | false | naabu resolves hostnames with its own public resolvers and recon passes no `-sr`/`-r`, so every lab name fails ("no valid ipv4 or ipv6 targets"). With no port scanner, httpx probes the resolved hosts on 80/443 and the common HTTP ports (`build_targets_from_dns`). |
| `purednsEnabled` | false | puredns validates against the public resolvers in `/app/recon/data/resolvers.txt` and would drop every lab name. |
| `useBruteforceForSubdomains`, `knockpyReconEnabled` | false | knockpy resolves with `8.8.8.8` unless it gets `--dns` (`knockpy/cli.py:283`), and recon never passes it: brute force finds nothing and only sends `.test` queries to a public resolver. Every lab word is in knockpy's bundled wordlist, so this changes once knockpy can be pointed at the system resolver. |
| `crtshEnabled`, `hackerTargetEnabled`, `subfinderEnabled` | false | public passive sources: nothing for `.test`, and their quotas and outages would show up as run-to-run coverage noise |
| `shodanEnabled`, `urlscanEnabled`, `otxEnabled` | false | vendor threat intel: would only send `.test` names, or a lab IP's real-world record, to a provider |
| `httpxProbeTlsInfo` | false | httpx `-tls-probe` also probes every SAN name it reads, and returns a random subset of them with a random scheme on each run, so two identical scans differ. With it off, httpx still reads the certificate (`-tls-grab`) and the SAN names reach the pipeline through the deterministic `certificate_san` merge. |
| `jsReconEnabled` | **true** | off by default; `js-only.v2.api` exists only in `/static/app.js` |
| `jsReconDependencyCheck` | false | otherwise JS recon queries the npm registry for every harvested package name |

Discovery for an ENUMERATE group therefore comes from the certificate SANs httpx
reads (`-tls-grab`) and from JS recon: deterministic, and enough for every
expectation below except brute force.

## Lab limitations (preflight, 2026-10-20)

Each tool was checked against a lab name from the host network
(`--network host`, as recon runs it). What does not work is accepted as a
limitation here, never fixed by changing product code.

| Tool | Resolves a lab name? | Consequence |
|---|---|---|
| dnspython (recon image) | yes, `127.0.0.53` | DNS, TXT ownership and the SPF/DMARC checks work |
| httpx | yes; `-tls-grab` returns web1's SANs | probing and certificate-SAN injection work |
| katana | yes | crawling works (`/static/app.js`, `/openapi.json`) |
| nuclei | yes (with or without `-system-resolvers`) | vuln scan works |
| naabu | **no**: own public resolvers | disabled (see settings) |
| tlsx | **no** for `host:port` targets: own resolvers | the tlsx SAN path is not exercised; httpx's SAN path is |
| knockpy | **no**: hard-coded `8.8.8.8` | no brute force: `dev.eu.corp` and `staging.dev.eu.corp` are never discovered, and a `*.eu.corp` group discovers nothing |
| masscan | n/a: **bypasses the kernel route** | must stay disabled (see settings) |
| amass | not checked (off by default; own resolvers) | |
| DNSSEC check (dnspython via the stub) | **no**: systemd-resolved answers SERVFAIL to every DNSKEY query while DNSSEC is off, for any domain | `check_dnssec_missing` reads the error as "unknown": no `dnssec_missing` finding, lab or not |

## Tooling

| File | Purpose |
|---|---|
| `snapshot_graph.py` | Snapshot one project's graph (sets of Domain, Subdomain, ExternalDomain, IP:port, BaseURL, Endpoint, Vulnerability, DNS findings, coverage gaps) and recon JSON. Read-only, tenant-scoped Cypher over Neo4j's local HTTP port. |
| `compare_snapshots.py` | Diff two snapshots as sets, ignoring measured run-to-run variance (`--volatile`) and reporting intended changes (`--allow`) separately. Exit 1 on any unexpected difference. |
| `nwlab_mcp.py` | A minimal inbound-MCP client (token from `MCP_SERVER_TOKEN_LAB`). |
| `run_scan.py` | One full recon of a lab project through MCP `start_recon`: the routing gate first, the container log followed into `recon.log`, `get_recon_status` polled once a minute, then a snapshot. `--resume` follows a scan already running. |
| `create_scenario.py` | Create one scenario's project over MCP from `expected_results.yaml` (`internal`), then print its `preflight_scope_check`. |
| `check_lab_traffic.py` | The E2E-B traffic assertions over one run's window (access logs + captures). |
| `lab_toggle.sh` | Per-run host switches (`plain-fixed`, `x8443 on`), through runtime includes. |
| `expected_results.yaml` + `validate_nested_wildcards.py` | The scenario expectations once nested wildcards ship, asserted through MCP `query_graph` (needs `graph:cypher`): `validate_nested_wildcards.py U3 <projectId>` prints PASS/FAIL per check. |

The token and passwords are read from `.env` inside each command and never printed.
