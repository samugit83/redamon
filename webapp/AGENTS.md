## CRITICAL RULES - NON-NEGOTIABLE

<!-- Add a rule only if an agent breaks it while working elsewhere AND cannot
     discover it from the file being edited. Component patterns belong in a
     scoped skill. See the root AGENTS.md for repo-wide rules. -->

- **NEVER write a user's own agent skill (`UserAttackSkill`) except through
  [userSkillWrites.ts](src/lib/userSkillWrites.ts).** It holds the per-user lock
  that makes the unique-name check and the 1,000-skill cap exact, and writes the
  audit row. Names are compared by a key computed IN SQL
  ([userSkillNames.ts](src/lib/userSkillNames.ts)), never in JavaScript.
- **ALWAYS pass a written `attackSkillConfig` through
  `normalizeUserSkillToggles`** ([userSkills.ts](src/lib/userSkills.ts)), or
  through `validateCrossFieldRules`, which applies it and replaces the value. A
  user skill is on only when its toggle is `true` (missing is OFF, in the form,
  the tooltip, the agent payload and the agent), at most 20 of the owner's
  skills may be on, ids the owner does not have are dropped, and a quarantined
  skill cannot be turned on. Write project rows that change toggles through
  Prisma, never raw SQL, so `updatedAt` moves and an open form gets a stale
  save instead of reverting the change.
- **NEVER answer a failure with the exception's text, and never let the
  browser drop its cause.** A route's catch answers `internalError(err,
  '<fixed sentence>')` ([routeErrors.ts](src/lib/routeErrors.ts)): `{error,
  code}`, where `code` is the Prisma or Neo4j code, the errno or the class,
  because `error.message` can quote query values, target data or keys. A handler
  without try/catch is wrapped in `withRouteErrors` (Next's own 500 has no body);
  a service that failed answers `upstreamFailureResponse` /
  `upstreamErrorResponse`. The browser reads a failure with `readApiError` /
  `fetchJson` ([apiError.ts](src/lib/apiError.ts)), whose message carries the
  code and HTTP status, so a screenshot is enough to tell the causes apart.
- **NEVER check ownership or admin rights outside
  [src/lib/authz/](src/lib/authz/); call `can()` / `projectAccess()`.** A route
  asks its permission through `requirePermission` ([guards.ts](src/lib/authz/guards.ts)),
  `requireSelfPermission` or `requireSessionPermission`, lists projects through
  `visibleProjectsWhere()` and per-user rows through `ownsRow()`; an inline
  `project.userId === user` or `role === 'admin'` is a second policy that the
  next permission or sharing change misses ([authzStaticGuard.test.ts](src/lib/authz/authzStaticGuard.test.ts)
  fails on one). The route's manifest entry names the same permission
  ([routePermissions.test.ts](src/lib/authz/routePermissions.test.ts)).

## TECH STACK

Next.js 16 (App Router, Turbopack) · React 19 · TypeScript · Prisma 6 (Postgres) ·
custom CSS design-token system (`src/styles/{base,components,themes,tokens}`, no
Tailwind) · Vitest 4. Runs in the `webapp` container; build via Docker.

## PROJECT STRUCTURE

```
src/app/          App Router routes + API route handlers (src/app/api/**)
src/components/   React components (shared primitives, incl. useAlertModal, in src/components/ui)
src/context/      React context providers        src/providers/  provider wrappers
src/hooks/        hooks                          src/lib/        client/server utilities
src/types/        shared TS types                 src/middleware.ts  edge middleware
server_actions/   Next.js server actions          prisma/schema.prisma  data model
```

The plugin platform (always on; plugins themselves are installed on demand) is
`src/lib/plugins/`, its routes `src/app/api/{plugins,plugin-gateway,plugin-runner,internal/plugins}/`,
its UI `src/components/plugins/` and `src/app/plugins/`; the `plugin-platform` skill holds its rules.

## COMMANDS

```bash
# All commands run against the webapp image or an `npm ci`'d webapp/ (never global node)
cd webapp
npm run test          # vitest run --no-file-parallelism (full parallelism OOMs the box)
npm run type-check    # tsc --noEmit
npm run lint          # next lint

# Prisma schema changes: db push, NOT migrate
docker compose exec webapp npx prisma db push
```
